# Pitfalls Discovered 2026-07-08

## Git: NEVER Commit Without Asking User
The Dispatcher (Hermes) must ALWAYS ask the user before running `git commit` or `git merge`. The user controls ALL git operations. This applies even when Governor approves — ask first, commit only after user says yes.
- Wrong: `git add -A && git commit -m "..."` (auto-commit)
- Right: `git diff --cached --stat` → show user → ask "Mau saya commit?" → wait for answer

## Vite Circular Chunk = Blank Production Page
When adding a new dependency to `manualChunks` in `vite.config.ts`, circular dependencies between chunks cause blank pages in production but work fine in dev mode.
- Symptom: Dashboard works on `npm run dev` (port 6869) but blank on production build served by server.js (port 6868)
- Root cause: `manualChunks: { ui: ['recharts'], vendor: ['react', ...] }` creates circular dependency because recharts depends on react
- Fix: Merge new deps into the `vendor` chunk: `vendor: ['react', 'react-dom', 'framer-motion', 'recharts']`
- Debug: `curl -s http://localhost:6868/assets/index-XXX.js` to verify JS files are served with correct MIME type

## Cache Hit Rate Formula
- Wrong: `cache / (input + output)` → nonsensical percentages (e.g. 4904%)
- Correct: `cache / (cache + input)` → valid 0-1 ratio (e.g. 0.673 = 67.3%)

## curl -I (HEAD) vs curl -s (GET) on Node.js Server
Node.js `http.createServer` only handles GET/POST by default. `curl -I` sends HEAD requests which return 404 or misleading Content-Type.
- Pattern: If `curl -I` returns `Content-Type: application/json` for `.js` files but `curl -s` returns correct `application/javascript`, server is fine — HEAD just isn't handled.
- Rule: Always use `curl -s` (GET) for testing static file serving and MIME types.

## .env Variable Naming: PROVIDER vs PROVIDER_ID
`spawn-worker.sh` reads `${PROVIDER:-aic}`. If `setup.sh` writes `PROVIDER_ID=xxx` instead of `PROVIDER=xxx`, workers fail to spawn because model path is wrong.
- Always verify: `setup.sh` writes same variable names that `spawn-worker.sh` reads.
